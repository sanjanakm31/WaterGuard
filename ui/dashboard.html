How protection works

Device A sends a signed command. Windows checks its identity, freshness, signature, nonce, register access, and operating range.

Only a command that passes every check is forwarded to the controller. A blocked command cannot write its requested value.

Start-to-finish presentation

Open the full beginner presentation script

  1. Connect Device A in Ubuntu to the Windows IPv4 address. Show System health on Windows.
  2. Set chlorine to 1.80 ppm and send. Show ALLOW and the plant's new chlorine value.
  3. Set valve to 70% and send. Show ALLOW and the new valve state.
  4. Enter chlorine 25.00 ppm. Show BLOCK / unsafe_setpoint. Explain that the requested value was never forwarded.
  5. Open Security demonstrations on Ubuntu and run the controlled suite. Show why each rejection occurred.
  6. Select an ALLOW or BLOCK row on Windows. Open Validation trace to explain each real check.
  7. Open Encryption proof: command, canonical evidence, hash, HMAC, AES nonce, ciphertext, decryption, verified comparison.
  8. Open SQLite explorer to show the actual stored ciphertext. Open the same database in DB Browser if requested.
  9. Run the one-bit tamper demonstration. Show TAMPERED for the copy and INTACT for the original.
  10. Open Test results. Report the measured counts and any errors honestly. Stop with the Windows launcher's Stop button.
