WHY THESE CHANGES
1. Dependency installation: original requirements.txt already contained all
   Python libraries. Added a checker and a setup-only script; the normal setup
   now checks TShark/Npcap access and PyShark parsing before launching.
2. Live detection: a PyShark monitor observes live traffic and writes encrypted
   ALERT events, separately from the gateway's actual ALLOW/BLOCK decisions.
   It handles fragmented/out-of-order WCP packets and avoids treating a TCP
   retransmission within one stream as a repeated command on a new connection.
3. Remote bypass: controller defaults to 127.0.0.1. In the two-computer layout,
   gateway and controller share the trusted computer, and a remote attacker
   cannot connect directly to the controller's port. This is not isolation
   against malicious programs already running on the trusted computer.
4. Benchmarking: matched safe writes are measured directly and via the gateway;
   five attack workloads are measured; exact returned event IDs select internal
   timings so unrelated traffic/ALERTs do not contaminate samples. Transport or
   controller failures are reported separately from security false positives.
5. Timing: gateway WCP timing starts after complete message receipt. Validation
   and Modbus forwarding times are separately recorded. Client RTT includes
   evidence encryption/storage. Neither is labelled pure CPU time.
6. Startup testing: tolerate legitimate chlorine decay during a slow Windows
   controller startup instead of requiring an exact unchanged chlorine value.

SECURITY BOUNDARIES RETAINED
WCP uses authentication, not transport encryption. Native Modbus is confined
to the trusted controller connection. AES protects evidence payloads/exports;
HTTPS protects the browser connection. Searchable database metadata remains
readable. Per-record tamper detection does not establish deletion-proof history.
Live capture observes traffic; it is not a network interception mechanism and
cannot withdraw a packet already sent. Gateway validation supplies prevention.
Chlorine decay and flow drift remain part of the original toy process model.

WINDOWS SQLITE HANDLE FIX
-------------------------
Evidence-store operations now close every SQLite connection explicitly after
commit/rollback.  Python's sqlite3 connection context manager does not close
the underlying handle by itself; on Windows that kept temporary test databases
locked during cleanup.  A regression test now verifies the lifecycle directly.
